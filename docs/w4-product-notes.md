# Week 4 product decisions

Sam has a few spare minutes between classes and finds images while exploring New York.
Keep the main interaction short: one real image, two specimens, one selection.
Use large touch targets and visible A, B, and S keyboard hints.
Show a brief saved state only after the database confirms both votes.
Retain the current pair after a network failure so Sam can retry.
Load another pair after a confirmed duplicate without counting another selection.
Explain Google sign-in at the point where rating needs authentication.

Fresh unseen pairs give Sam a reason to return.
An exhausted queue must say it is exhausted.
Do not fabricate a daily count, streak, leaderboard, or new content.
An upload-to-generation-to-duel path lets users contribute material from their own lives.
Persist generation provenance and prompts using the verified course API and schema.
Offer sharing only after the source media and its access rules are verified.

Punnett can improve the caption experience with side-by-side judgment and stage-specific recovery.
Keep the image visible while comparing caption text.
Preserve the user's place when a request fails.
The notebook should show persisted selections with stable specimen codes and newest entries first.
Retain the existing personal bench as a separate section.

The visual system uses night-mode teal, lilac interference highlights, and refracted glass edges.
Keep decorative effects behind content.
Retain readable solid surfaces for text and forms.
Respect reduced motion and keyboard navigation.
Keep the page usable at 320 pixels.

These are implementation criteria, not claims that the blocked voting and generation flows are complete.
